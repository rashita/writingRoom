# Writing Room

執筆に使う原稿・資料・ダッシュボードを、ひとつの作業室にまとめる macOS 向けデスクトップアプリです。

ローカルのフォルダをプロジェクトとして開き、テキストの編集や HTML ダッシュボードの閲覧をタブで行えます。原稿は通常のファイルとして保存するため、ほかのエディタや Git と組み合わせて使えます。

現在は開発中の試作版です。自動保存・未保存内容の復旧には対応していません。

今後の機能候補は[見出し機能の検討メモ](docs/heading-features.md)に記録しています。

## 主な機能

- フォルダ単位で原稿や資料を開くファイラーとタブ
- UTF-8 テキストの編集、文字数表示、文字サイズの変更
- HTML・CSS・JavaScript で作れるダッシュボード
- タブとステータスバーを隠す全集中モード
- 複数プロジェクトと、原稿を別窓で開く子ウィンドウ
- 最近使ったプロジェクトと、前回の作業タブの復元
- 原稿の差分を確認して、そのファイルだけをコミットする進捗記録（試作）
- 原稿・プロジェクトのコミット履歴と、色分けした変更差分の閲覧

## 開発環境で起動する

macOS 上で Node.js と npm、Rust と Cargo、Xcode Command Line Tools が必要です。

```sh
git clone https://github.com/rashita/writingRoom.git
cd writingRoom
npm ci
npm run dev
```

### アプリをビルドする

```sh
npm run build
```

生成先は `src-tauri/target/release/bundle/macos/Writing Room.app` です。現在の設定では macOS の `.app` を生成します。署名・公証は設定していません。

### CodeMirror 6 の管理

CodeMirror 6 は他のツールでも利用するため、`/Users/Tadanori/cm6-build` で一元管理しています。このプロジェクトでは、その成果物を `src/cm-bundle.js` にコピーして運用します。`src` はアプリの配信対象ディレクトリです。テキスト編集欄はこのバンドルの CodeMirror 6 を使用しています。Markdown の装飾や折りたたみなどは追加せず、プレーンテキストとして編集します。

バンドルを更新する場合は、共通管理側の `src/index.js`（エクスポート）や依存関係を必要に応じて変更し、次の手順でビルド・コピーします。

```sh
cd /Users/Tadanori/cm6-build
npm run build
cp dist/cm-bundle.js /Users/Tadanori/Dev/writingRoom/src/cm-bundle.js
```

生成済みの `src/cm-bundle.js` は直接編集せず、変更は共通管理側に反映してください。共通管理側の変更時は他の利用先への影響も確認します。このプロジェクトではコピーした成果物を Git で管理するため、通常の起動・アプリビルドに共通管理ディレクトリは不要です。

### 見出しへ移動

テキスト原稿を開いて「移動 → 見出しへ移動…」（⇧⌘O）で、Markdownの見出し一覧を一時表示できます。現在カーソルがある節の見出しが最初に選択されます。上下キーで選び、Enterまたはクリックでその見出しに移動します。Escまたは「閉じる」なら編集位置を変えずに戻ります。見出しは階層に応じて字下げし、コードブロック内の記述は除外します。本文の装飾は行いません。

### 書籍全体の見出しへ移動

「移動 → 全体の見出しへ移動…」（⌘⌥⇧O）で、原稿フォルダ直下の `.md`・`.markdown`・`.mmd`・`.txt` の見出しをファイル名の連番順にまとめます。未保存の編集も反映し、選択すると該当ファイルの見出しへ移動します。ファイル内の見出し一覧（⇧⌘O）から「全体の見出し」ボタンでも開けます。全体一覧からは「ファイル内の見出し」で元の一覧へ戻れます。

原稿フォルダの既定値は `Drafts` です。変更する場合はプロジェクト直下の `.writingroom.json` に `"manuscript_folder": "原稿フォルダの相対パス"` を指定します。設定画面はまだありません。サブフォルダは対象に含めません。

### 見出しの本文の開閉

⌘H → P（⌘Hの後にP）または「移動 → 直近の見出しを閉じる」で、カーソルが属する直近の見出しの本文を閉じます。下位見出しも含め、同じ階層以上の次の見出しの直前まで隠します。カーソルは対象の見出し行へ移ります。⌘H → Oまたは「移動 → 直近の見出しを開く」で開き直せます。表示された `…` のクリックでも開けます。親見出しを開いても、閉じていた下位見出しは閉じたままです。本文・保存内容・文字数は変わらず、タブ切り替えでは開閉状態を保持します。最初の見出しより前の本文や、閉じる本文がない見出しでは何もしません。待機中はEscでキャンセルできます。

⌘Hは見出し操作、⌘Kは履歴操作の起点です。全体の開閉は今後の候補で、まだ未実装です。

### 外部エージェントの起動（テスト）

プロジェクトを開いた状態で「エージェント → codexを起動」を選ぶと、AppleScript経由でGhosttyに新しいウィンドウを作成し、そのプロジェクトフォルダで `codex "プロジェクトを開始します"` を実行します。起動済みのGhosttyがあれば、そのインスタンスを使います。AppleScript対応のGhostty（1.3.0以降）とCodex CLIのインストールが必要です。初回はmacOSからGhosttyの操作許可を求められることがあります。`/bin/zsh -lic` を通して起動します。未保存の原稿は自動保存しません。

## 基本的な使い方

1. ファイルメニューの「プロジェクトを開く…」（⌘O）からフォルダを選択します。直下に `.writingroom.json` を作成します。
2. 別のプロジェクトを開くと新しいメインウィンドウになります。
3. `index.html` があればダッシュボードとして表示します。別名のHTMLも「HTMLを選ぶ…」から選択できます。index.htmlがない場合はフォルダ内のHTMLを名前順で検出します。
4. HTMLがなければ作成するか確認します。「作成しない」は設定に記録し、次回は確認・表示しません。ファイラーの「ダッシュボード」「HTMLを選ぶ…」から後で追加できます。
5. ファイラーからフォルダ、HTML、UTF-8テキストをタブで開きます。「別窓」でテキストの子ウィンドウを開けます。

「表示 → ファイラー」で、プロジェクト直下のファイラーをいつでも開けます。すでにそのタブがある場合は切り替えます。ファイラーのタブを閉じてしまった場合も、このメニューから開き直せます。

ファイラーのフォルダは通常クリックで同じタブ内に表示し、⌘クリックで別タブに開きます。別タブで開く際、同じフォルダのタブがあればそこへ切り替えます。「↑ 上へ」も同じ操作で親フォルダを開けます。

作業タブはドラッグ＆ドロップで並び替えられます。移動先のタブの左半分にドロップすると手前、右半分なら後ろへ移動します。プロジェクトのタブの並び順は次回起動時にも復元します。
6. テキストはファイルメニューの「保存」または ⌘S で保存します。テキストタブを右クリックすると「子ウィンドウで開く」を選択できます。同じファイルの編集内容はアプリ内で共有されます。メインウィンドウを閉じると子ウィンドウも閉じます。未保存の編集があれば確認します。

### 新しい原稿とウィンドウ

プロジェクトを開いた状態で ⌘N（ファイル → 新しい原稿）を押すと、空の「無題」タブを作ります。最初の ⌘S で保存ダイアログを表示し、プロジェクトフォルダを初期位置として保存先と名前を選べます。保存先はプロジェクト内に限り、既存ファイルの上書きには対応していません。キャンセルした場合は無題タブを保持します。保存後は通常の原稿として編集できます。

無題の原稿はタブを閉じる際に破棄の確認を表示し、ウィンドウを閉じる際やアプリ終了時も未保存原稿として確認します。無題タブは次回起動時の復元対象にはなりません。プロジェクト全体の記録やコマンド実行の前には、無題の原稿を保存するか閉じてください。ウェルカムページでの ⌘N は何も行いません。

⇧⌘N（ファイル → 新しいウィンドウ）は、常に新しいウィンドウにウェルカムページを開きます。現在のプロジェクトは開いたままです。

### HTML ダッシュボード

サンプルとして [dashboard.html](dashboard.html) を同梱しています。

ダッシュボードタブを右クリックして「ソースを編集」を選ぶとHTMLの編集タブを開けます。

HTMLは通常のHTML・CSS・JavaScriptを記述できます。相対パスの画像・CSS・スクリプトに対応し、相対リンクのフォルダやテキストをアプリで開きます。ダッシュボードはsandbox付きiframeで実行され、Tauriのファイル操作APIは公開していません。`localStorage` 等の同一オリジン機能は使用できません。

### プロジェクト設定

`.writingroom.json` に、フォルダごとのダッシュボードを記録します。

```json
{
  "version": 1,
  "dashboards": {
    "": "index.html",
    "資料": "overview.html",
    "原稿": null
  }
}
```

キーはプロジェクト直下からのフォルダ相対パスです。`null` はダッシュボードを表示しない指定です。

## 名前付きコマンドの登録

プロジェクトを開いて「作業 → コマンドを登録・編集…」を選ぶと、「PDFを作る」「make pdf」のような名前とコマンドを登録できます。追加・編集・削除した後、「保存」で反映します。同じ名前は重複して登録できません。各コマンドの「このコマンドを既定とする」で一つを選び、⌘Bで保存して実行できます。登録が一つなら自動で既定になります。追加時は既定を維持し、既定を削除すると残った先頭が既定になります。以前の設定で既定が未指定の場合も先頭を使います。

登録内容はプロジェクト直下の `.writingroom.json` の `tasks` に保存します。既定コマンドのIDは同じ設定ファイルの `default_task` に保存します。各項目は `id`（一意な識別子）、`label`（表示名）、`command`（コマンド文字列）を持ちます。「作業」メニューに登録順でコマンドが並び、選ぶとすぐ実行できます。表示するコマンドは操作中のプロジェクトに合わせて切り替わり、子ウィンドウでは所属プロジェクトのコマンドを表示します。プロジェクト直下を作業フォルダとして `/bin/zsh -lic` で対話ログインシェルの設定（`.zshrc` など）を読み込んで実行し、終了後に成功・失敗、標準出力、標準エラーを表示します。実行前に、子ウィンドウを含む同じプロジェクトの未保存ファイルを保存します。保存や編集内容の同期に失敗した場合はコマンドを実行しません。複数ファイルの途中で保存に失敗した場合、それ以前の保存は保持されます。

実行画面を閉じても処理は続き、終了状態はステータスバーに表示します。出力は実行終了後にまとめて表示します。対話入力・停止・常駐するプレビューサーバーの管理には対応していません。

### 成果物と実行ログ

コマンドごとに成果物の相対パス（例：`Build/book.pdf`）と「成功後に自動で開く」を設定できます。自動で開く設定は既定でオフです。成果物はプロジェクト内のファイルを指定します。

成果物は既定でこのアプリのタブに開きます。「既定の外部アプリで開く」を選ぶと、macOSの `open` コマンドと同じアプリで開きます。この設定は既存のコマンドで未指定の場合もアプリ内が既定です。自動・手動どちらも同じ開き方を使います。Markdownはソース編集、PDF・HTML・画像は表示用のタブになります。すでに開いているタブは最新の内容で更新しますが、成果物に未保存の編集がある場合は更新せず停止します。対応していない形式は外部アプリを選んでください。

成功後は結果画面の「成果物を開く」から手動でも開けます。アプリ内で開けた場合は結果画面を閉じます。自動で開く設定では、成功して成果物を開けた場合に結果画面も閉じます。コマンドの失敗、成果物が見つからない場合、開く操作の失敗では結果画面を残します。

「作業 → 直近のコマンドログを確認…」で、そのウィンドウの最後の実行結果を確認できます。ログは直近1件、出力は最大20万文字をメモリ上に保持し、次の実行結果で置き換え、ウィンドウを閉じると消えます。

## 全集中モード

切り替え時はタブとステータスバーが約200msで薄くなりながら上下へ退き、本文領域が広がります。解除時は逆の動きです。macOSで「視差効果を減らす」が有効な場合は即時に切り替えます。

テキストタブを表示中に ⌘⌥F（Command + Option + F）または「表示 → 全集中モード」で切り替えます。タブとステータスバーを隠し、本文に集中できます。同じショートカットまたは Esc で通常表示に戻ります。日本語変換中の Esc は変換操作を優先します。本文の編集位置を保ったまま切り替え、⌘S で保存できます。ファイラーやHTML表示には適用せず、別の種類のタブに切り替えると解除します。モードはウィンドウごとに独立し、次回起動時には通常表示に戻ります。全画面表示とは独立しています。

⌘W は現在のタブを閉じます。最後のタブを閉じてもウィンドウは残り、タブがない場合は何もしません。未保存の編集がある場合は、タブの閉じるボタンと同じ確認を表示します。ウィンドウを閉じる操作は ⇧⌘W です。

## 最近使ったプロジェクト

入り口ページのタブ領域に、最近開いたプロジェクトを新しい順で最大20件表示します。クリックするとそのウィンドウで開き、作業タブへ切り替わります。ホバーでフルパスを確認できます。右クリックメニューで「別ウィンドウで開く」「履歴から外す」を選べます。履歴から外してもプロジェクトのファイルは変わりません。

作業中はファイルメニューの「最近使ったプロジェクト」から別のプロジェクトを開けます。フォルダが移動・削除されても履歴は保持し、見つからない旨を表示します。履歴はアプリのデータディレクトリ内の `recent-projects.json` に保存し、次回起動時も表示します。

## タブの復元

アプリ起動時はウェルカムページを表示します。最近使ったプロジェクトや「プロジェクトを開く…」から開くと、そのプロジェクトの最後のタブの種類・順序・選択状態を復元します。全タブを閉じた状態も記憶します。

前回の終了時に開いていたプロジェクトがあれば、ウェルカムページに「前回の作業を再開」を表示し、クリックすると前回のプロジェクトウィンドウとタブをまとめて復元します。その起動中に別のプロジェクトを開いても、再開対象は前回終了時の状態を維持します。既に開いているプロジェクトは追加で開かず、そのウィンドウにフォーカスします。「前回の作業を再開」は起動ごとに一度利用できます。ウェルカムページだけを表示して終了しても、前回の作業状態は保持します。

作業中は「ファイル → 新しいウィンドウ」（⇧⌘N）で、新しいウィンドウにウェルカムページを開けます。明示的に閉じたプロジェクトウィンドウは次回起動時の再開対象から外しますが、手動でプロジェクトを開いたときのタブ復元には影響しません。

状態はアプリのデータディレクトリ内の `workspace-state.json` に保存します。プロジェクトの設定 `.writingroom.json` とは分けて管理し、原稿の本文は含めません。未保存の編集があれば従来どおり終了確認を表示し、復元時にはディスク上の内容を読み込みます。子ウィンドウ、ウィンドウ位置、カーソル位置は復元対象外です。移動・削除などで復元できない対象はスキップして通知します。プロジェクトは絶対パスで識別するため、フォルダを移動すると以前のタブ状態は引き継がれません。


## 文字サイズ

テキストタブを表示中に「表示」メニューから文字を大きくする（⌘=、⌘+も使用可）、小さくする（⌘-）、標準に戻す（⌘0）を選べます。12〜32pxの範囲で1pxずつ変更し、標準は16pxです。全集中モードでも操作できます。

サイズはすべてのテキストタブ・別窓で共有し、アプリのデータディレクトリ内の `editor-preferences.json` に保存します。再起動後も維持します。行間は文字サイズの1.9倍で、本文幅は従来どおりです。

## コミット履歴を見る

「履歴 → この原稿の履歴…」で、編集中の原稿のコミット履歴を表示します。「履歴 → プロジェクトの履歴…」では、プロジェクトフォルダ内の変更を含むコミットを表示します。現在のブランチ（HEAD）からたどれる記録が対象です。

左に記録のメッセージ・日時・短いコミットIDを表示し、選ぶと右に作成者、メッセージ全文、変更ファイルの概要と差分を表示します。追加行は緑、削除行は赤で色分けします。履歴は50件ずつ読み込み、「さらに読み込む」で過去の記録を追加できます。最初のコミットの差分にも対応しています。マージコミットの差分は最初の親との比較です。

閲覧時に原稿の保存やGitのステージの変更は行いません。原稿の履歴は現在のファイルパスを対象とし、名前変更前のパスは追跡しません。Gitとリポジトリが必要です。

## Git による進捗記録（試作）

Gitで追跡済みの原稿を編集タブで開き、「履歴 → この原稿を記録…」（⌘K → K）を選びます。未保存なら保存を確認し、最新のcommitからの差分を表示します。メッセージを入力して「記録する」を押すと、この原稿1件だけをcommitします。他のファイルのステージ済み変更は含めません。Gitとリポジトリ、既存のcommit、Gitのユーザー設定が必要です。新規原稿は「履歴 → このファイルを追跡に追加」で、その原稿1件だけをGitに追加（ステージ）できます。未保存なら保存を確認します。追加後は「この原稿を記録」でcommitしてください。追跡済みのファイルには何も変更しません。pushはターミナルで行ってください。

確認後に原稿やHEADが変わった場合は停止します。記録に失敗したときは入力画面にGitのエラーを表示します。

| この原稿の履歴 | ⌘K → L |
| 開発者ツールの表示／非表示 | ⌘⌥I |

原稿の編集中に ⌘K を押すと、履歴操作の次のキーを待ちます。続けて K で「この原稿を記録」、L で「この原稿の履歴」を開きます。二つ目のキーは ⌘ を離しても、押したままでも使えます。⌘K 単独では記録しません。待機中だけステータスバーに候補を表示し、Escでキャンセルします。クリック、ウィンドウの切り替え、タブの切り替え、日本語入力の変換開始でも待機を解除します。未割り当ての通常キーは原稿に入力せず待機を終了し、⌘Sなど別のショートカットは待機を終了して通常どおり実行します。日本語変換中は連続入力を開始しません。⌘Kで待機に入ると、二つ目のキーを受け取る非編集要素へ一時的にフォーカスを移します。日本語入力がオンでもK／Lが本文の入力に回らないようにし、操作またはキャンセル後は元の編集位置へ戻ります。

テキスト編集中に「移動」メニュー、または ⌥⌘[ / ⌥⌘] で、同じフォルダの番号が1つ前／後のファイルを開きます。`chapter001.md` → `chapter002.md` のように、拡張子の直前（拡張子がなければ名前の末尾）の数字を加減し、ゼロ埋めを保ちます。移動先がなければ「作成／キャンセル」を確認し、「作成」で空のファイルを作って開きます。現在のタブを移動先の原稿に差し替えます。移動先がすでに開いている場合は、そのタブに切り替えます。未保存の編集がある場合は「保存して移動／キャンセル」を確認します。`000`より前には進まず、`999`の次は`1000`になります。

初めて表示するテキストファイルは先頭にカーソルを置きます。同じウィンドウで再訪したファイルは、前回のカーソル位置・選択範囲・スクロール位置を復元します。記録はタブを閉じても保持し、ウィンドウを閉じると消えます。別ウィンドウとは共有せず、原稿ファイルにも書き込みません。


未保存のタブは閉じるボタンの位置に ○ を表示し、保存すると × に戻ります。○ をクリックした場合も、未保存の編集について確認してからタブを閉じられます。

## 現在の制約

- UTF-8のテキスト編集（10 MiBまで）。Markdownはソースを編集します。
- ファイラーは一覧・フォルダ移動・ファイルを開く操作に対応しています。連番以外の新規原稿作成、削除、名前変更、ドラッグ操作は今後の拡張対象です。
- 外部でファイルが変更された場合、保存を停止して上書きを防ぎます。編集内容をコピーして保管した後、プロジェクトを閉じて開き直してください。
- 原稿の自動保存、未保存内容の復旧、外部変更の自動取り込みは未実装です。
- ダッシュボードのファイルを保存した後は、そのタブを再選択すると表示が更新されます。

## 開発

Tauri 2 と Rust、バニラ JavaScript / CSS / HTML で構成しています。フロントエンドのフレームワーク・バンドラー・エディタライブラリは使用していません。ネイティブダイアログには Tauri 公式の dialog プラグインを使用しています。

```text
src/                    フロントエンド
src-tauri/src/          Rust のアプリ処理
src-tauri/capabilities/ Tauri の権限設定
src-tauri/icons/        アプリアイコンと原画像
tests/                  JavaScript のテスト
dashboard.html          ダッシュボードのサンプル
```

### 検証コマンド

```sh
npm run check
npm test
```

`npm run check` は `src/app.js` の構文を確認します。`npm test` はタブ復元・全集中モード・文字数表示の JavaScript テストと、Rust のテストを実行します。

依存関係の再現性を保つため、`package-lock.json` と `src-tauri/Cargo.lock` を管理対象に含めています。

### 開発者ツール

エディタの表示・入力に関する変更と確認結果は[エディタの変更・動作確認メモ](docs/editor-notes.md)に記録しています。

「表示」→「開発者ツールの表示／非表示」（⌘⌥I）で、現在のウィンドウのWeb Inspectorを開閉できます。ビルド済みのMacアプリでも使用できます。ElementsでHTML・CSS、ConsoleでJavaScriptの実行やエラーを確認できます。ダッシュボードはiframe内にあります。検証ツールで変更したCSSは一時的なので、残したい変更はHTMLやCSSのファイルに保存してください。

Tauriのdevtools機能はmacOSで非公開APIを利用するため、App Store向けに配布する際にはこの機能を無効化する必要があります。

「履歴 → プロジェクトを記録…」では、子ウィンドウを含むプロジェクト内の未保存原稿を保存し、プロジェクトフォルダ内の新規・変更・削除の差分を表示します。確認後にメッセージを付けて一括commitできます。Gitの除外対象となる未追跡ファイルは含みません。新規原稿を事前に追跡へ追加する必要はありません。既存のcommitが必要です。プロジェクトがリポジトリの一部でも、フォルダ外の変更は含めず、フォルダ外のステージ済み変更も保持します。差分確認やキャンセルではステージを変更しません。commitが失敗した場合、追加したステージ内容は残ることがあります。

## タイプライターモード

テキストタブで「表示 → タイプライターモード」を選ぶと、入力やキーボードでのカーソル移動に合わせて、カーソルのある表示行を編集領域の中央へ寄せます。原稿の先頭・末尾にも表示上の余白を設けます。ホイール操作やマウスでの選択では中央へ戻さず、次の入力・キー移動で追従を再開します。日本語変換中は追従を控え、変換終了後に中央へ寄せます。見出しへ移動した際も中央へ寄せます。

設定はウィンドウごとに独立し、テキストタブ間で共通です。全集中モードと併用できます。次回起動時はオフになります。
