# 見出し機能の検討メモ

記録日: 2026-10-22

Markdown原稿の見出しを、執筆中の現在地の把握、移動、構成の検討に活用する。編集欄はCodeMirror 6へ移行済み。見出し一覧からの移動と見出し単位の開閉を試作し、ユーザーが試用中。以下の実装内容・キー割り当ては最終決定ではなく、使い心地を見て変更する。未実装の候補の採用・実装順も未決定。

## Sticky Scroll（直近の見出しの固定表示）

スクロールした表示箇所の直前にある見出しを、編集欄の上端に固定表示する。

- カーソル位置ではなく、表示中の本文を基準にする。
- 表示するのは直近の見出し一つだけ。親見出しを階層で並べる必要はない。
- たとえば見出し3の本文を表示しているなら、その見出し3だけを表示する。
- 次の見出しが画面上端を通過すると、表示を切り替える想定。

見出しのMarkdown記法をそのまま表示するかなど、細部は未決定。Markdownの構文解析を利用し、コードブロック内の `#` などは見出しとして扱わない方針が候補。

## その他の候補

| 機能 | 執筆時の用途・想定する動作 |
| --- | --- |
| 見出しへジャンプ | ショートカットで見出し一覧を呼び出し、選んだ場所へ移動する。見出し名での絞り込みも候補。 |
| 前・次の見出しへ移動 | キー操作で節を移動し、節ごとの読み返しや執筆を助ける。 |
| 見出しごとの折りたたみ | 今扱わない節を隠す。すべて折りたたんで構成を眺める使い方も想定。折りたたみ自体は将来的に必要という認識。 |
| 現在の節を選択 | 見出しから節の末尾までを一度に選択し、コピー・移動・削除などにつなげる。 |
| 節ごとの文字数 | 現在の節や見出し一覧で文字数を確認し、構成と分量のバランスを把握する。 |
| 節を前後に入れ替え | 本文と下位見出しをまとめて移動し、説明の順番を組み直す。 |

未実装の候補については、節の範囲、操作方法、ショートカットを実装前に検討する。Sticky Scrollの採用も未決定。

## 構想：現在の原稿から書籍全体へ見出しの視野を広げる

2026-10-23のユーザーのアイデア。以下は構想の記録であり、方式の採用や実装の指示ではない。

書籍原稿の執筆では、いま編集している原稿の見出しだけでなく、書籍全体の見出しも情報として必要になる。開いているファイルとその見出しを表示するレベルから、一つ上のレベルとして、他の章のファイルと見出しを並べる機能を考えたい。そこで、全体の対象にどのファイルを含めるかが課題になる。

ユーザーが挙げた執筆・表示の方式は次の三つ。

| 方式 | 内容 |
| --- | --- |
| 一つのファイルに全章を書く | 全章の本文を一つのファイルに入力する。ファイル内の見出し一覧が書籍全体の見出し一覧になる。 |
| フォルダ内の本文を連続表示する | あるフォルダにある原稿を、一つのタブの中で連続して並べる。 |
| フォルダ内の見出しだけを抜粋する | 特定のフォルダを指定し、そこにあるファイルの見出しをまとめて表示する。本文はファイルごとに扱える。 |

### 検討上の考え（アシスタント）

中心にあるのは「編集する単位」と「構成を見渡す単位」を別々に選べるようにすること。章ごとにファイルを分けていても、全体の構成を参照できるとよい。現在のファイルと書籍全体を切り替えても、同じ見出しの階層・現在地・移動の考え方を使えると、視野を広げる操作として理解しやすい。

最初の検討対象としては、フォルダを指定して見出しだけを集める方式が扱いやすそう。本文の連続表示には、ファイル境界、保存先、境界をまたぐ編集など別の設計が伴うため、全体の見出しが必要という要求とは分けて検討できる。

対象の指定だけでなく、章の順序も必要になる。フォルダ内の全ファイルで十分か、資料・メモを除外したいか、ファイル名順でよいか、明示的な章順を持ちたいかは未決定。将来、対象ファイルと順序を記した「書籍の構成」を持つ案も考えられるが、まずフォルダ指定で足りるかを見たい。

### 対象と順序の基本前提（2026-10-23追記）

ユーザーの考えとして、基本的に `Drafts/` に連番付きのファイルが保存されていることを前提にするのが最も自然。書籍全体の見出しを集める際は、このフォルダを対象とし、連番に沿って原稿を並べることを基本案とする。

原稿をまとめるために `book.toml` などを作ることもあるが、必ず作成するわけではない。そのため、全体の見出し表示に構成ファイルを必須としない。構成ファイルを利用する場合の扱いは今後の検討事項であり、現時点ではその形式や優先順位を決めない。

全体表示でも、執筆中の章・節がどこにあるかを示し、他章の見出しからそのファイルの該当箇所へ移動できると、参照と執筆がつながる。全体の見出しをどこに・どのくらい常時表示するかも今後の検討事項。

## 試作済み：一時的な見出し一覧

「移動 → 見出しへ移動…」（⇧⌘O）で表示。登場順・階層の字下げ付きの一覧を、現在のカーソルが属する節を起点に開く。上下キーとEnter、またはクリックで移動し、Escで取り消す。絞り込みは未実装。

## 試作・試用中：直近の見出しの本文の開閉

2026-10-22時点の試用版。ユーザーはこの状態でしばらく試す予定。下記は現状の動作の記録であり、確定仕様ではない。

| キー操作 | 試用中の動作 |
| --- | --- |
| ⌘H → P | カーソルが属する直近の見出しの本文を閉じる。本文中からでも実行できる。 |
| ⌘H → O | 直近の見出しの本文を開く。親を開いても、下位見出しの開閉状態は維持する。 |

- 閉じる範囲は、対象見出しの末尾から、同じ階層以上の次の見出しの直前まで。下位見出しも含む。
- 閉じた際はカーソルを対象の見出し行へ移す。隠した部分に表示する `…` のクリックでも開ける。
- 「移動」メニューからも個別の開閉を実行できる。2ストロークの待機中はEscでキャンセルできる。
- 開閉で本文・保存内容・文字数は変えない。タブ切り替えでは開閉状態を保持する。
- 見出し一覧から隠れた場所へ移動すると、移動先が見えるように開く。

### キー体系の検討経緯と未決定事項

起点で操作の系統を分ける。⌘Kは履歴系として維持し、見出し系にはHeadingのHを使う。⌘Hは現在のアプリで「アプリを隠す」に登録されていないため、まず試用し、支障があれば変更する方針。2打目は隣り合うO／Pをユーザーが選択した。

Org modeの操作体系を参考にしているが、そのまま採用するとは決めていない。見出し行でのTab、見出し系の2ストロークでのTab、表示状態の巡回などは引き続き検討対象。本文中の単独Tabに開閉を割り当てる案には、入力操作として意外な動作になる懸念がある。

「すべて閉じる／すべて開く」も必要という認識だが、まだ未実装でキー割り当ても未決定。見出し左の三角による開閉も未実装。
